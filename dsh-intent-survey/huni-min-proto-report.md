# H-UNI 最小原型 · 统一 AS 意图对象 vs 分散载体代价对比（V3 窄口径实证）

**副题**：统一意图对象（单一可验证上下文）在「一致性维护 / 验证开销」上的确定性对比——S1 事件脚本
**证据等级**：**C 级**（确定性原型会计，非真实网元；全部 disputed，仅方向性）
> 生成：2026-10-15 · 代码：`dsh-research/src/intent/`（types / dispersed / unified / compare）
> 上游口径：`docs/domain-intent-survey.md` §3.4 机制假说 H-UNI、§四 V3（disputed）、§5.2-②下一步

## 1. 背景与问题

IETF 目前没有统一 AS 路由意图对象：起源（ROA/ROV）、上游授权（ASPA）、对等角色（BGP Roles/OTC）、
转发承诺（FC-BGP）四类意图载体分属**证书库**与 **BGP 属性**两个平面，组合验证与跨家族一致性由运营者
手工承担（V1 verified）。TRIZ 矛盾分析给出的最高信息增益方向是「统一 AS 意图中介/聚合层」（原理 #24），
即 H-UNI 设计假说。V3（disputed）：**H-UNI 统一意图中介层可降低一致性维护开销**——此前仅有文献级
可行性论证、无直接实验（`docs/domain-intent-survey.md` §5.1-⑤）。本报告给出最小原型的第一轮窄口径实证。

## 2. 口径（本原型诚实声明的边界）

**只量化「对象级操作次数」+ 跨家族一致（coherent）+ 漂移窗口（drift）**，四维代价：

| 维度 | 分散载体（基线） | 统一对象（H-UNI） |
| --- | --- | --- |
| 对象写入 writes / 签名 signOps | 四家族独立对象；每对象写 = 1 write + 1 signOp；跨家族变更写放大 | 每 AS 单一对象，变更原子 = 1 write + 1 signOp |
| 验证检索 lookups | origin AS 4 lookup（ROA/FC/ASPA/Roles），其余不同在途 AS 2 lookup | 路径上每不同 AS 1 lookup（四面一次取齐） |
| 验签 verifyOps | ROA/FC/ASPA 各 1（Roles 无签名，RFC 9234） | 每存在的对象 1 次 |
| 漂移 drift | 多对象写非原子→ `failAfterWrite` 部分生效 → 窗口++ | 单对象原子 → 恒 0 |

**明确不覆盖**（V3 反证维度，需真实网元/专项设计）：表达力 ↔ 可判定性的取舍（ASPA 刻意 O(1)
可判定的既有纪律）、增量部署与认证链、缓存失效半径、信令与错误处理、规模化（AS 数扫描）。
故本原型结论**不得**视为 V3 的升级证据，V3 维持 **disputed**（仅方向性支持）。

## 3. 方法（确定性，可复现）

同一事件脚本 S1（4-AS / 7 事件 / 2 处部分失败 / 3 条验证路由）在三态上分别跑：

1. **分散（含失败）**：`failurePlan = {1:1, 6:2}`——事件 1 splitPrefix（2 步：ROA+FC，只写 1 步）
   与事件 6 revokeAll（4 步，只写 2 步）部分生效 → 陈旧跨家族引用残留、drift++。
2. **分散（无失败基线）**：纯写放大对照。
3. **统一（忽略失败）**：单对象原子写、无部分窗口。

每态执行 seed → events → verify（3 条路由）→ audit，全量计数。验证判决含 origin / forwarding /
provider / roles / **coherent**（`!(forwarding=committed && origin≠valid)` 的自相矛盾检测）/
compliant。审计含跨家族 join 扫描（分散）vs 对象内核查（统一）。

复现：

```bash

node --test "src/intent/intent.test.ts"   # 6 用例
node --test "src/**/*.test.ts"            # 全量 194
```

## 4. 结果（S1）

### 4.1 对象级代价（全量 = seed + events + verify + audit）

| 仓库 | writes | signOps | lookups | verifyOps | drift | auditViolations |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 分散（基线，含失败） | 14 | 14 | 23 | 6 | **2** | **2** |
| 统一（H-UNI） | 14 | 14 | **8** | **3** | **0** | **0** |

- 事件阶段写放大（无失败基线）：分散 **11** vs 统一 **8**（比值 **0.73**）
- 验证+审计 lookups：**8** vs **23**（比值 **0.35**）
- 验签 verifyOps：**3** vs **6**（比值 **0.50**）
- 审计 lookups：**1** vs **3**（比值 **0.33**）

> 注：writes/signOps 全量打平（14 vs 14）——种子 + 大多数单对象事件两者等价；差距集中在
> **多对象变更（splitPrefix / revokeAll）的写放大**（无失败基线 11→8）与**验证 / 审计的检索与验签**。

### 4.2 路由判定（最终状态）

| 路由 | 分散 compliant | 统一 compliant | 分散 coherent | 统一 coherent |
| --- | ---: | ---: | ---: | ---: |
| R1（100 / 10.0.0.0/25 / [100,400]） | ❌阻断 | ✅合规 | ✅一致 | ✅一致 |
| R2（100 / 10.0.0.0/24 / [100,400]） | ❌阻断 | ❌阻断 | ❌**矛盾** | ✅一致 |
| R3（100 / 10.0.0.0/25 / [100,200,300]） | ❌阻断 | ❌阻断 | ✅一致 | ✅一致 |

R2 即分散态跨家族矛盾的直接演示：splitPrefix 部分失败后 ROA 已迁移到新前缀、FC 仍引用旧前缀
→ 验证时 `origin=notFound` 且 `forwarding=committed` **自相矛盾**（coherent=false）；
统一对象内原子迁移 → 无此矛盾。R1 显示统一态 FC 与 ROA 同对象同步迁移 → 合规；分散态 FC
未迁移（未承诺）→ 阻断。R3 为对照组（上游 200 已撤销，两态均阻断）。

### 4.3 V3 窄口径评估

`evaluateV3Narrow(S1)`：六维全部通过 → **supported = true**——对象级代价各维统一 ≤ 分散、
无部分漂移、审计违规不更多。

## 5. 证据分级与诚实标注

- **证据等级 C 级**：确定性原型会计（非真实网元）；对应仓库把此类证据一律标 disputed、仅方向性。
- **V3 判定维持 disputed**：本原型只在「对象级操作 / 一致性窗口」窄口径给出方向性支持；不触碰
  表达力↔可判定性、增量部署、缓存、信令等 V3 反证维度，**不升级** V3。
- **散/统 writes 打平**：本原型不声称统一在写入侧全面更优——写放大收益集中在多对象变更场景；
  分散态的代价主要显性体现在验证/审计检索与验签侧。
- **revokeAll 部分失败**：分散态撤销为 5 类对象顺序写，写入数不足时陈旧 provider 引用 / 陈旧
  FC / 陈旧 ROA 残留，审计跨家族 join 捕获 2 处违规；统一态单对象原子删除 + 他对象引用清理。

## 6. 局限与下一步

1. **确定性子集**：S1 为 4-AS 单脚本；未做 AS 数 / 事件数扫描，规模化不在此轮。
2. **无真实网元**：未涉及证书库/信令/缓存失效；FRR/VPP 等真实网元上手后需复测。
3. **角色语义简化**：roles 合规仅以「向 provider 宣告 = 违反」简化裁决；未建模 OTC 等。
4. **下一步**：AS 数 × 事件数参数扫描 → 真实网元原型 → 结合 ASPA 可判定性纪律重估 V3。

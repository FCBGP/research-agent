# 科研绘图工作流（Prompt → Draw → Status → Embed）

## 定位
绘图是**paper 报告产出环节**的配套能力，不是领域知识也不是研究结论。
本 skill 定义在 paper/report 流程里怎么生成可信、可追溯、可排版入稿的配图，
以及为什么图片必须绑定**输出路径 + 生成参数**（随会话持久化，能回跳重生成）。

## 何时用
- 论文/报告需要示意/概念图（架构、报文时序、矛盾映射、机制对比、数据流）。
- 已有实验结果想“以图释文”，但绝对不拿生成图**冒充**实验数据曲线
  （实验统计图必须来自 research_campaign 的四口径结果，不是本 skill；本 skill 只产出
  插图/示意图/封面类）。
- 需要垫图改稿：以既有图作参考（风格参考 0.4 / 内容参考 0.7），生成变体。
- 何时图、何时表：能一句话说清的趋势/类型/架构 → 图；需要精确数值/多列对比/逐项追溯 → 表。
  一张图只讲一件事；讲不清就拆图或改表，绝不一张大杂烩。

## 标准流程
1. **写提示词**（科研绘图 paradigm，建议中英皆可）：
   `科研绘图：<主题>，<图型：架构图/时序图/对比图/机制示意>，<元素清单>，<配色：冷色/统一色系>，<用途：论文 Figure X / 报告配图>`
   - 图型规范：架构图 → 分层/方框+箭头；时序图 → 时间轴+报文标注；对比图 → 明确横纵轴与类别色；
     机制示意 → 因果链+关键标签。
   - 配色：优先统一色系（如冷色系蓝绿灰），同语义同色，避免彩虹渐变；深色底慎用于打印。
   - 分辨率/字号：按用途选 2K（报告配图常用）→ 4K（论文大图）；文字/标签要可读（宁大勿小）。
2. **调参数**（research_draw）：
   - `provider`：local（本机 Qwen-Image-2.1，mflux，非驻留、并发 1；**唯一支持垫图 edit**）
     或 api（OpenAI 兼容 images API，需 baseURL/apiKey/modelId，key 支持 ${VAR} 引用）。
   - `aspect`（默认 16:9）/ `resolution`（长边 1K/2K/4K，默认 2K）/ `quality`（低20/中30/高50步，默认高）。
   - `seed` 固定可复现；垫图 mode=edit 时给 editPreset=style|content + 强度。
3. **轮询**：research_draw 提交后 bounded 等待；长任务返回 jobId → 用 research_draw_status
   轮询 phase（queued→running→succeeded/failed），拿 `outputPath`（固定
   `images/image-YYYYMMDDHHmmSS.png`）与 `artifactId`。
4. **回填报告**：把 `outputPath` 与生成参数（prompt 摘要/尺寸/seed/模型）作为 traceable 图注
   写进 research_paper 报告；无法内嵌外部图片的场景至少附路径 + 参数，保证可复现。
5. **归档**：每次生成随会话持久化（artifact draw: note，可按 sessionId 过滤）；结论性图表仍须
   绑定实验 artifact（policy：没有实验数据不得声称“实验验证”）。

## 纪律（对齐 Research Agent Policy）
- 生成图 = 插图/示意，不是证据：涉及数字/曲线的图必须来自实验/测量的原始数据。
- 配图需可追溯：报告里每个配图注明 prompt/参数/输出路径，复盘可重生成。
- 垫图仅 local（v1）；api 模式不支持垫图——需要改稿时切 local 或改提示词重画。
- host research-draw `config.enabled=false` 时面板与工具均不可用：别硬调，先检查 profile 配置。

## 文字/图形错乱处理（Qwen-Image-2.1 文字短板，2026-10-21）

**根因**：图像扩散模型按「语义像素」出图，**不真正排版文字**——小字号、密集、中文、技术符号
（eBGP/iBGP、AS64500、IP 段、箭头旁标注）最容易错乱/缺笔/重复/鬼符；图形（方框/箭头/连线）数量一
多也会粘连、错位、断线。这是**模型固有局限，不是参数调不好**，只能规避或用结构图兜底。

### 0 · 先分类：这张图「文字是不是关键信息」
- 文字**只是装饰**（大标题 1-2 个、图名、盖章类）→ 图片模型可用，错字接受度取决于用途。
- 文字**是关键信息**（架构图分层标签、时序图报文名、流程每步文字、对比图轴标签/图例）→
  **不要指望图片模型渲染正确文字**，按下面 3 / 4 方案走。
- 打分：图上需要**≥4 处文字**或**任一处小字号中文/技术符号（eBGP、AS…、IP…）** → 判为
  「文字关键」，不进图片模型。

### 1 · 提示词纪律（降低文字错乱，图片模型内兜底）
- **文字量压到最少**：整图**≤2-3 个短标签**，宁大勿小；优先英文短词（eBGP / BGP / AS），
  中文只放标题级，且**单字/词不贴边**。
- 明确给「文字负约束」：`图中文字极少，只保留 <X>/<Y> 两个标签，其余一律不要出现任何文字`、
  `标签大而清晰，不与箭头/边框重叠`、`不要小字号文字`、`不要花式字体，用无衬线体`。
- 结构要「少而大」：方框/箭头/连线数量限制（能讲清即可），避免一张大杂烩——讲不清就拆图或改表。
- 分辨率/画质拉满再抽：**2K→4K、高画质（50 步）** 文字命中率更高；**固定 seed 多抽几版**
  挑错字最少的一版（错乱随 seed 波动）。negativePrompt 填 `乱码, 错别字, 文字错误, 密集小字,
  squiggly text, misspelled text`（部分后端/mflux 支持程度不一，不保证，仅锦上添花）。
- 垫图 edit 只改变风格/内容，**不会修复错字**；文字已错的参考图做 edit 大概率把错字带进结果。

### 2 · 结构性示意图 = 最可靠通路（文字关键时首选）
精确标签、精确布局的**架构图 / 时序图 / 流程示意 / 数据流图** → 用**结构化制图**而非图片模型：
- SVG / Mermaid（本仓库已有 markdown-mermaid、scientific-schematics 等技能）直接画文本标签，
  字体/位置程序可控，**绝不产生错字**。
- 这类图进 paper/报告时用「矢量/文本图」标注来源（如由 research 结构化生成，非 research_draw），
  别混在 image-gen 记录里冒充生图。

### 3 · 两阶段混合（推荐：既好看又零错字）
1) 第一阶段：图片模型生成**「无文字/极少文字」的艺术底图**——提示词里显式要求
   `图中不要出现任何文字，不要任何字母数字，纯图形构图`（底图负责配色/质感/视觉冲击）。
2) 第二阶段：用 **PIL/SVG 把精确文字叠加**到底图上（程序控制字体/大小/位置/描边），
   或让 research 结构化生成 SVG 文字层后合成 PNG。
3) 验收：整图字都对、位置不遮挡 → 进 paper；任何一处错字 → 重抽底图或改走方案 2。

**已落地（2026-10-21，research_draw 面板）**：
- 提示词下方新增「两阶段混合：无文字底图模式（推荐）」开关——勾选后提交时自动追加
  「图中不要出现任何文字、字母或数字」负约束；
- 历史区上方新增「文字叠加」卡片——底图下拉选历史中仍在本地的图片，标签区每行一个
  （`文字 | x,y | @字号 | #颜色 | b加粗`，缺省=底部居中白字黑描边），点「合成文字」由
  本机 python3 + Pillow 精确叠字（零错字），成品 `image-…-overlay.png` 进历史 stack、可看大图。
- 后端探活：`/api/research.draw.config` 返回 `overlay.supported`（本机 python3 + Pillow 可用
  才显示合成卡片；不可用给出 `pip install Pillow` 提示）。
- 工作流建议：先勾「无文字底图」生成 → 检查底图构图 → 在「文字叠加」卡片补标签合成 → 大图验收。

### 4 · 验收纪律
- 生成后**必须人工/人工辅助检查文字与图形**，不是「图出来就行」。
- 错字且文字是核心信息 → **弃用此图**，走 2 / 3 方案；错字仅为装饰 → 可接受，或局部裁掉错字区。
- 报告图注必须写实际产出通路（image 模型 / 结构化 / 混合），保证可复现、不误当「生图全对」。

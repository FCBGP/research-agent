## 0. 一句话结论

域间路由的「意图」目前**没有统一的端到端表达/承载/验证环**，现状是三段式分裂：

- **单侧授权事实 = 强锚点**（RPKI ROA/ROV：把「谁被允许起源什么」做成密码学事实）；
- **声明式策略 = 弱载体、语义零散**（IRR/RPSL、BGP community：有表达力、无密码学绑定、语义本地定义）；
- **广义 IBN 意图（偏好/排序/优化/时变）= 结构性缺席**（RFC 9315 的 intent 定义 vs RPKI 快照式授权对象不匹配）。

**课题「网络连接意图 · 多源共识三视图」恰好填补核心一环**：把散落在不同载体的意图声明（SHOULD）、行为观测（IS）、异常告警（ALERT）对齐成可核验的共识视图——本质是一个跨载体的 *intent-representation + intent-assurance* 桥，而 RPKI 是这条链上最强的密码学锚点。

## 1. 口径：intent vs policy（RFC 9315）

| 概念 | 定义（RFC 9315） | 映射到课题 |
|---|---|---|
| **intent（意图）** | 声明式、可验证的**期望结果/目标**，不规定"怎么做" | 声明视图 (SHOULD)：要达成的连接意图 |
| **policy（策略）** | 约束系统**行为选择**的规则集合，是"怎么做" | 机制层：ROV/过滤/community 动作 + 本地策略（RFC 7454） |
| intent 生命周期 | User / Translation-IBS / Network Ops 三空间；外部综述补充闭环组件 `expression → translation → resolution → activation → assurance`（[ÉTS IBN Survey](https://pure.etsmtl.ca/en/publications/a-survey-on-intent-based-networking)） | 行为视图 (IS)=assurance 的观测源；异常视图 (ALERT)=resolution/verification 的偏差告警 |

**关键取舍**：`intent` 与 `policy` 是**两个正交维度**，不能混用。调研表明——RPKI/ASPA/BGPsec 属于「密码学声明的**授权事实**」（部分接近 intent 的声明侧），community/RPSL 属于「**策略信令**」，两者都要，但把前者当"意图语言"使用是常见误判（BGPsec 误区即属此类）。

## 2. 逐机制判定表（表达/承载机制全景）

| 机制 | 判定 | 承载的意图侧面 | 核心依据 | 一句话理由 |
|---|---|---|---|---|
| **ROA / ROV** | ✅ 强 | 起源授权意图（谁可起源我的前缀；含 maxLength 子前缀粒度） | [RFC 6480 §3](https://www.rfc-editor.org/rfc/rfc6480)、[RFC 6811](https://www.rfc-editor.org/rfc/rfc6811)、[RFC 7115](https://www.rfc-editor.org/rfc/rfc7115)、[RFC 9582](https://www.rfc-editor.org/rfc/rfc9582) | 密码学签名、链式验证、单向声明——窄义授权型 intent 的唯一**强载体** |
| **ASPA** | 🟡 途中 | 传播/路径授权意图（顾客→上游，谁可为我传播），比 ROA 多一维 | draft-ietf-sidrops-aspa-{profile,verification}、[RFC 9774](https://www.rfc-editor.org/rfc/rfc9774)；NIST [ASPA 验证材料](https://datatracker.ietf.org/) | 仍是授权集、无偏好/排序；对象 profile 与验证算法**均未 RFC 化**，外部线索佐证 |
| **BGPsec** | ❌ 非意图 | 不是表达，是**运行期证明**（已走路径被逐跳授权） | [RFC 8205/8206](https://www.rfc-editor.org/rfc/rfc8205) | 证明"已发生的授权"，**不声明期望/禁止的路径**——最常见误解，明确排除 |
| **IRR / RPSL** | 🟡 弱 | 声明式路由策略意图（import/export 对照、route 对象授权） | [RFC 2622](https://www.rfc-editor.org/rfc/rfc2622)、[RFC 2650](https://www.rfc-editor.org/rfc/rfc2650) | 有表达力但**无密码学绑定、数据可失准**（正是课题以 RPKI 作锚点的原因），只能作辅助声明证据 |
| **BGP community** | 🟡 弱 | 运营信号型意图（RTBH、NO_EXPORT 等传播控制）；取值语义由各 AS 自定 | [RFC 1997](https://www.rfc-editor.org/rfc/rfc1997)、[RFC 7999](https://www.rfc-editor.org/rfc/rfc7999)、[RFC 9047](https://www.rfc-editor.org/rfc/rfc9047) | 语义**本地化、无全局标准表、可被劫持者注入**——行为侧提示、绝不可作权威 |
| **SLURM** | 🟡 本地 | 本地化意图（RP 从本地视图**过滤掉**或**补加** RPKI 断言） | [RFC 8416](https://www.rfc-editor.org/rfc/rfc8416)。draft-ietf-sidrops-rtr-slurm(8664) | 只对本 RP 生效（原子生效），是**本地例外层**，不进全局声明面 |
| **SCION** | ✅ 路径意图 | **真路径选择意图**：端主机选路 + AS 对其分段做密码学授权（Path Authorization） | [draft-dekater-panrg-scion-overview](https://datatracker.ietf.org/doc/draft-dekater-panrg-scion-overview/) | 唯一把"路径意图"搬进**数据面承载**的架构；全新、非 BGP 增量 |
| **IBN 意图线（域间）** | ⚠️ 缺标准 | 域内成熟（闭环五部件）；域间无统一意图语言/验证标准 | ÉTS IBN Survey；[RFC 9315](https://www.rfc-editor.org/rfc/rfc9315)；[BGP 验证攻坚](https://www.cs.princeton.edu/~jrex/papers/)；HTTP [APNIC IRV](https://blog.apnic.net/) | Princeton 佐证 BGP 验证须对照 **high-level intended policy** 静态分析——域间正缺这个对照层 |
| **BGP CAR（RFC 9871）** | 🟡 前沿 | 跨域传输网 **intent-aware path**（color-aware routing） | [RFC 9871](https://www.rfc-editor.org/rfc/rfc9871) | 标准化努力里**最接近 IBN 域间落点**，但场景受限（underlay transport/color） |
| **课题·多源共识三视图** | ✅ 补缺口 | 连接意图**全维观测**：声明(SHOULD)+行为(IS)+异常(ALERT) 共识对齐 | KT2 实施方案 | 共识保证 + RPKI 密码学锚 + 行为/异常交叉——恰是上述机制缺位的接缝 |

## 3. 关键缺口（Gap，5 条）

- **G1 · 声明盲区**：RPKI 仅覆盖 40–50% 前缀；未覆盖区无密码学声明可核验，ROV 未强制时验证结果亦无效（partial deployment，[RFC 7115](https://www.rfc-editor.org/rfc/rfc7115) 增量部署视角、IMC 2019 部署研究）。
- **G2 · 单侧 vs 双向往语义**：现有授权载体都是**单侧声明**（资源持有者/顾客视角）；「传播授权（ASPA，顾客→上游）」与「接收偏好」无统一的**双向意图图**。
- **G3 · 广义意图结构性不支持**：偏好/排序/优化/时变/条件在 RPKI 家族**没有字段**（快照式签名授权 + 慢仓库更新）；maxLength 还体现「粒度表达力 ⇔ 伪造子前缀面」张力（[RFC 9319](https://www.rfc-editor.org/rfc/rfc9319)）。
- **G4 · 缺 assurance 环路**：声明视图（SHOULD）与行为视图（IS）之间**没有一致性校验闭环**——IBN 的 assurance 环节在域间缺失，异常只能靠事后告警（RFC 7908 泄漏分类也仅在行为面）。
- **G5 · 权威层级混排**：各载体可信度**跨数量级**（RPKI 强 / IRR 弱 / community 无语义），但现有工具多以单源为准——**多源共识是自然解法**，亦是课题核心价值。

## 4. 课题建议（3–5 条，直接对接 KT2 三视图）

1. **锚点分级不变，显式建模盲区**：RPKI 密码学声明继续作最高权重锚（R0 判定规则）；把「无 ROA/无 ROV 覆盖」显式建模为声明视图 `UNKNOWN` 态，由行为视图 + 共识 **兜底**而非当缺失丢弃（对 G1）。
2. **补双向意图边**：在共识层补「顾客→上游」传播授权（对应 ASPA 语义）与「接收偏好」两类**有向边**，形成意图图；ASPA 观察先行（即便未 RFC 化，算法已验证）对 G2。
3. **引入 assurance 闭环指标**：输出 `intent-compliance`（声明 vs 行为达成度）与 `drift`（偏差）作为三视图共识的产品化口径，直接对齐 RFC 9315 assurance 组件与 BGP 验证文献的 intended-policy 对照（对 G4）。
4. **community 攻击面列为显式风险**：community 可被劫持者注入、语义本地化，只作**行为侧提示**并入共识证据链，同时把「社区注入检测」纳入异常视图候选（对 G5、G2 安全面）。
5. **保持表达模型「可翻译」**：跟踪 ASPA 转 RFC、[RFC 9871 BGP CAR](https://www.rfc-editor.org/rfc/rfc9871)、SCION path-authentication 三条外部线，把课题意图模型做成**可映射到标准资本的 open schema**，避免自闭环方言（对 G3）。

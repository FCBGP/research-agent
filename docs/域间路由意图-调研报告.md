域间路由意图调研报告：跨 AS 声明式安全策略的表达、验证与机制方向
# 一、背景与目标

## 1.1 研究背景

BGP（Border Gateway Protocol）是互联网域间路由的事实标准协议，其核心语义是「基于策略的路径向量」：每个自治系统（AS）依据本地导入/导出策略决定向邻居公告哪些前缀、接受哪些路由、如何选择最佳路径[1]。由于 BGP 默认信任对等方公告、缺乏内建的完整性验证，域间路由长期暴露在起源劫持、路径伪造与路由泄漏三类核心攻击之下；其中路由泄漏已被标准化组织系统分类为「违反 BGP 拓扑关系假设的前缀传播」问题[2]。

传统 BGP 以「属性 + 本地策略」承载管理意图，意图与执行机制强绑定、难以跨 AS 校验。随着网络自动化与「网络即代码」理念的普及，IETF 提出了意图驱动网络管理（Intent-Based Networking，IBN）范式，将意图定义为「网络管理期望达成的目标，而非具体如何达成」[3]。然而，IBN 的主流标准化工作集中于网络管理平面（自动化与闭环保障），尚未系统投射到跨 AS 安全域：域间路由安全的意图对象东零西落地分布在 RPKI 证书对象、BGP 属性与第三方数据库之上，缺乏统一的承载与验证语义。

本报告目标：(1) 系统盘点域间路由安全领域既有的「意图载体」及其表达力/可验证性；(2) 定位「统一承载完整意图上下文」的缺口（Gap）；(3) 通过 TRIZ 机制方向分析与确定性模拟实验，产出一组可核验的机制假说（统一 AS 意图聚合层、sidecar 抽取、预签署推断、威胁自适应四类），并诚实标注证据等级。

## 1.2 术语与口径

本报告区分以下陈述类型（与既有实验口径一致）：

- Fact：可由一手文献或标准原文直接核验的事实陈述。
- Result：确定性模拟实验的测量结果（绑定实验 artifact）。
- Hypothesis：机制方向类假设。本报告全部 TRIZ 派生假说一律为 source=triz、confidence=0.5，写作「待核验」；不因被引用或出现在本报告而升级为已核验 claim。
- Assumption：实验设定、检索范围等必要假定。
- Interpretation：基于 Result 与文献的解读。

实验口径：本报告实验采用确定性路由模拟引擎 RouteEngineSim（engine=sim），同一 mulberry32 种子（20261016）可复现；因当前沙箱无 FRR/VPP 守护进程，所有实验在 sim 环境中如实标注，结论证据等级以上限 C 级计。检测率判定阈值 supportThreshold=0.8 为外部设定口径，非本报告推导。

# 二、域间路由意图的现状盘点

本章对「域间路由意图」的既有承载形态做一轮盘点。按对象的存放位置划分，现有载体分属以下几个面：

1. 证书库平面（RPKI）：以 RPKI 证书基础设施签发签名对象，经 RPKI-Router（RTR）协议（[RFC 8210](https://www.rfc-editor.org/info/rfc8210)）分发给验证方。代表性对象包括路由起源授权（ROA，见 [RFC 9582](https://www.rfc-editor.org/info/rfc9582)）与自治系统提供方授权（ASPA，[datatracker 草案页](https://datatracker.ietf.org/doc/draft-ietf-sidrops-aspa-profile/)）。

2. BGP 属性/协商平面：以 BGP 报文属性或能力通告承载，例如 BGP Roles 与 OTC 属性（RFC 9234，[RFC 主页](https://www.rfc-editor.org/info/rfc9234)）、能力通告（RFC 5492，[RFC 主页](https://www.rfc-editor.org/info/rfc5492)）、起源边界参数 maxLength（RFC 9319，[RFC 主页](https://www.rfc-editor.org/info/rfc9319)）以及转发承诺 BGP（FC-BGP，[I-D 全文](https://www.ietf.org/archive/id/draft-wang-idr-frameworkoffcbgp-00.txt)）。

3. 第三方/行为平面：IRR（Internet Route Registry）与 RPSL 注册库、声明式网络编程（DECLARE）、面向网络级路由策略配置的意图分析（[INM 2007 会议论文](https://conferences.sigcomm.org/sigcomm/2007/inm/papers/inm07-1569047333.pdf)）、以及机构级意图路由草案（[draft-li-teas-intent-based-routing](https://datatracker.ietf.org/doc/draft-li-teas-intent-based-routing/)）。

4. 工业界与政府标准化生态：社区托管平台的 ASPA 实践指南（[via-registry](https://www.via-registry.com/resources/what-is-aspa)）与美国国家标准与技术研究院（NIST）的域间路由安全项目（[NIST Robust Inter-Domain Routing](https://www.nist.gov/programs-projects/robust-inter-domain-routing)）。

本章仅为现状罗列（不引入编号引用）。盘点结论：四个承载面互相独立、各有表达力与验证能力的边界；「一个 AS 的完整路由意图上下文」目前不存在于任何单一对象中。

# 三、意图载体详析

## 3.1 载体总览与统一缺口

综合盘点，本报告将「域间路由意图载体」归纳为四类（详见表 8-2-1-1 四载体比较矩阵）：起源类（ROV+ROA）、角色类（BGP Roles+OTC）、上游授权类（ASPA）、转发承诺类（FC-BGP）。这四类对象互不相关，分属证书库与 BGP 属性两个平面；IETF 检索中不存在统一承载「完整意图上下文」的工作项；RFC 9315 定义的 IBN 属网络管理域，未投射到跨 AS 安全域。该观察对应 Gap 假说 C-intent-gap（第四章给出，第六章进入核验）。

## 3.2 起源载体：ROV + ROA

起源验证（Route Origin Validation，ROV）是当前部署最广的意图验证机制：验证方将收到的前缀公告与 ROA 对象比对，判定 Valid / Invalid / NotFound 三态，用于抑制伪造起源的劫持[4]。

ROA（Route Origin Authorization）作为承载「起源意图」的签名对象，其档案格式由 RFC 9582 定义（取代 RFC 6482，属于正式 RFC / Proposed Standard，而非草案级规范）[5]。ROA 的表达力低（仅授权「某前缀可由某 AS 起源」），但可验证性高（三态判定、依赖 RPKI 证书链）、部署成本低，是 RPKI 体系落地最彻底的意图对象；起源意图之外的上游授权、转发承诺等语义均不在 ROA 的承载范围内。

## 3.3 路径与角色载体

### 3.3.1 起源边界参数 maxLength

ROA 的 maxLength 字段限制「授权起源前缀的最长掩码」，用于收窄伪造子前缀的攻击面；RFC 9319 将其确立为 BCP 185，与 RFC 7115 的过滤建议互补[6]。

### 3.3.2 能力通告

BGP 能力通告（RFC 5492）允许在 OPEN 报文中协商扩展能力，是角色协商、多协议扩展等机制的握手基础[7]。

### 3.3.3 BGP Roles 与 OTC 属性

BGP Roles 在 eBGP 会话两侧显式协商对等关系（Provider / Customer / Peer / Route Server 等），配合 Only to Customer（OTC）传播属性实现路由泄漏的预防与检测；其验证语义是「收到即检」——收到公告即与已协商角色比对，不符合则拒收或降级[8]。

### 3.3.4 上游授权载体 ASPA

ASPA 是承载「上游授权意图」的签名 RPKI 对象：AS 号持有者在其对象中列出被授权作为上游传输提供方的一组 AS 号，验证方据此检查 AS_PATH 中关系是否与授权一致，可捕获 ROV 无法发现的伪造路径段与部分路由泄漏。ASPA 目前仍处于草案标准化阶段（draft-ietf-sidrops-aspa-profile 定义对象、draft-ietf-sidrops-aspa-verification 定义验证算法），尚未成为 RFC；其与 ROV 的组合验证效果见第六章实验。

### 3.3.5 转发承诺载体 FC-BGP

转发承诺 BGP（Forwarding Commitment BGP，FC-BGP）把「直连邻居的转发意图」以密码签名形式化：FC 是一个密码签名代码，用于证明 AS 在其直连跳上的路由意图；其目标是在 BGP-UPDATE 中同时认证 AS_PATH 属性、并在数据平面验证网络转发，即把意图从「接收即验证」推进到「转发即自证」[9]。FC-BGP 目前仅为个人 Internet-Draft（draft-wang-idr-frameworkoffcbgp-00，作者 Xu K, Wang X, Liu Z, Li Q, Wu J，清华大学，2023 年 10 月起草），未成为 RFC。FC-BGP 的深挖与机制方向见第八章专题。

## 3.4 行为与声明载体

### 3.4.1 声明式网络编程 DECLARE

在「以声明表达意图」的学术脉络中，SIGMOD 2006 的 DECLARE 系声明式网络编程是早期代表性工作：以 Datalog 风格的声明语言表达网络协议与策略，网络行为以递归规则声明、由执行引擎推导，是「用高层意图声明替代过程式状态机」的里程碑[10]。

### 3.4.2 INM 2007 意图分析

卡内基梅隆大学的 Levanti 等人在 SIGCOMM INM 2007 工作坊将「意图」用于网络级路由策略配置的离线性分析：基于「底层命令（route-map、prefix-list、filter-list）→ 高层目标」的硬编码映射，把邻居按共享意图聚类，生成并比较更新模式，属于「把配置反解释为意图」的经典范式[11]。

### 3.4.3 意图路由草案 draft-li

华为的意图路由草案 draft-li-teas-intent-based-routing 尝试以「策略块（policy block）」携带意图（含拓扑、起源、传播路径、偏好等字段）并在 RIB 上验证策略标签；该草案仅为 -00 版、已过期归档（最新版本 2021-10-25），反映意图在数据平面携带的早期探索方向[12]。

## 3.5 工业界与标准化生态

工业界与政府标准化侧的动态与本报告 Gap 分析直接相关：

- 社区托管平台 via-registry 于 2026 年发布「ASPA Explained: BGP Path Validation Beyond RPKI Origin Checks」实践指南（2026-07-12 发布、2026-10-01 更新），明确 ASPA 是签名 RPKI 对象、检查超越 ROV 的 AS_PATH、可捕获路由泄漏与伪造路径段劫持，并指出截至 2026 年 9 月其仍为 IETF 草案状态——从工业界侧面印证「上游授权意图尚未正式标准化」的判断[13]。
- NIST 的 Robust Inter-Domain Routing 项目（FY2025 口径）主导多年期 IETF BGP 安全/韧性规范（含 BAR-SAV 与 ASPA），修订域间路由安全指引（引用 SP 800-189 Rev.1 IPD，2025-01），维护 BGP-SRx 参考平台，并发布测试工具以加速 route-leak 缓解标准的采用[14]。

# 四、Gap 定位：统一 AS 意图上下文的缺失

综合第三章与第八章，本报告将核心 Gap 形式化为一条假说：

C-intent-gap（Hypothesis）——域间路由意图散布于 ROA / ASPA / BGP Roles / FC-BGP 四类互不相关的对象，无统一承载「完整意图上下文」的载体；跨对象的一致性维护与组合验证依赖手工协调。支撑证据（方向层面）：IETF 检索（datatracker，字段级）不存在统一工作项（检索词 asintent 命中 0）；四载体分属证书库与 BGP 属性两个平面；RFC 9315 的 IBN 属网络管理域、未投射到跨 AS 安全域。四类载体的表达力/可验证性/部署成本差异见第八章第 8.2 节比较矩阵——该矩阵即为 Gap 的量化依据。

该假说在第六章作为核验项 V1 进入核验（结论 trusted/verified，详见表 6-4-1-1）。

# 五、TRIZ 机制方向

## 5.1 矛盾分析与发明原理派生

本报告把「ROV 提升劫持检测率，但分散意图对象抬高验证与一致性复杂度」形式化为 TRIZ 技术矛盾：改善「测量精度（检测）」（参数 28）↔ 恶化「设备/系统复杂度」（参数 36），命中精选矛盾矩阵候选发明原理 #23（反馈）、#2（抽取）、#24（中介）。进一步沿矛盾空间展开：

- 矛盾一（表达力 ↔ 验证/部署成本，28↔36）→ 候选 #23 反馈、#2 抽取、#24 中介 → 派生假说 H1-1 / H1-2 / H1-3（H1-3 即 H-UNI）。
- 矛盾二（全局可信/覆盖上升以补盲区 ↔ 跨域共识收敛延迟/开销上升，27↔25）→ 候选 #11 事先缓冲、#10 预操作、#23 反馈 → 派生假说 H2-1 / H2-2 / H2-3。
- 矛盾三（意图动态性上升 ↔ 配置可运维性/可审计性下降，35↔33）→ 候选 #1 分割、#15 动态化、#25 自服务 → 派生假说 H3-1 / H3-2 / H3-3。

## 5.2 候选原理筛选

对信息增益最高的一号矛盾，对 #23 / #2 / #24 三个候选做「对照既有工作」筛选（结果见表 5-2-1-1）：

- #23 反馈：ROV/ASPA 已是「收到即反馈验证」、FC-BGP 是转发承诺自证——该方向已被既有权衡内化，新颖性低。
- #2 抽取：RPKI 已把源验证抽取到证书库依赖方侧车（sidecar，RTR 客户端缓存），存在 off-path 先例（RFC 8210）；作为差分方向（sidecar 验证一致性）仍有待核验价值 → 假说 H1-2。
- #24 中介：用「统一 AS 意图聚合层」合并多类意图对象为单一可验证上下文——IETF 检索无既有实现（datatracker asintent=0）→ 信息增益最高，为核心 Gap 方向 → 假说 H-UNI。

其余候选（#11 / #10 / #1 / #15 / #25 等）的既有实现对照并入 5.3 假说状态备注。

# 八、FC-BGP 专题

## 8.1 意图粒度五级阶梯

FC-BGP 位于「转发承诺」这一较高意图粒度。为定位 FC-BGP 在意图语义空间中的位置，先给出意图的三层视图：意图声明层（SHOULD，基于 ROA/RPKI、ASPA、RPSL/IRR 的声明对象）、行为层（IS，基于 RouteViews / RIS 观测 BGP 公告/AS_PATH/起源分布）、意图验证层（ALERT，基于 ROV/BGPsec/行为-声明交叉验证）。其中「RPKI 未覆盖约 40% 前缀盲区」为既有 Fact（confidence≈0.85），即行为推断意图主要服务于该盲区。

在此基础上归纳意图粒度五级阶梯（表 8-1-1-1）。核心观察（Interpretation，confidence≈0.7）：意图语义粒度与「跨域可验证性 × 部署成本」负相关——粒度越细、语义越丰富的意图，越难在不引入大成本的前提下被跨域可信验证。

## 8.3 FC-BGP 的 Gap

结合 8.1 / 8.2：FC-BGP 把「意图」推进到数据面（AS_PATH 认证 + 数据面转发验证），是四载体中表达力最高、最接近「完整意图」语义的载体；但其「自证 + 部署成本高」使其当前可验证性居四载体最低。Gap 具体化为三点：

1. 平面割裂：FC-BGP 落 BGP 扩展平面，与证书库平面的 ROA/ASPA 之间无统一承接对象，跨平面组合验证（如「起源 + 上游授权 + 转发」一并校验）需要多机制协调。
2. 无统一工作项：FC-BGP 仅为个人 I-D，IETF 尚无官方工作项承载「转发承诺 + 其它意图对象」的统一上下文。
3. 表达力 ↔ 可验证性张力：最高表达力恰好落在最低可验证性端点，正是第五章矛盾一（28↔36）的实例。

# 九、结论

本报告对「跨 AS 声明式安全策略的意图表达与验证」给出阶段性结论：

1. 现状与 Gap：域间路由意图分布于 ROA / ASPA / BGP Roles / FC-BGP 四类互不相关对象，跨证书库与 BGP 属性两个平面；无统一承载「完整意图上下文」的工作项（C-intent-gap，V1 verified）。五级意图阶梯与四载体比较矩阵共同提示：意图粒度越细，「可验证性 × 部署成本」越不利；没有任何载体同时满足「高表达力 + 高可验证性 + 低部署成本」。
2. 实验核验：在本组确定性模拟（engine=sim）五指纹本下，加入意图验证后检测率由基线 0.093 升至 0.55–0.79（绝不为「0.8」），全部低于外部阈值 0.8（V2 verified）；ASPA 在 subprefix 上对 ROV 有 +0.060 增益、在 path-manipulation 上独立覆盖 ROV 盲区（C5 rejected）；20 格 sweep 汇总 supportedRate 70.0%（56/80）。以上均为 C 级证据，需真实网元复测。
3. 机制方向：所有 TRIZ 派生假说（H-UNI、H1-2、H2-2、H3-2）均为待核验假说（source=triz、confidence=0.5）；其中 H-UNI 当前判定为 disputed，H1-2 / H2-2 在文献面存在反证但仍保留为核验目标；未经 research_campaign 或 FRR/VPP 真实网元实验，任何一条都不得升级为已核验 claim。

口径确认提醒：本报告「检测 0.55–0.79」指五指纹本的检测率区间，不是总体宣称；「0.8」仅为外部判定阈值，不是测量到的检测率；sweep 的 supportedRate 与五指纹检测率为两套独立口径，引用时需区分。
